# 청주시 의정자료 정책주제 코딩 지침 0.1

2026-11-04 · 분류 기준 개발 단계. 사람 검토 완료0건, 주제 분류·관심사 점수 산출0건.

## 근거와 적용 범위

CAP(Comparative Agendas Project)의 정책 의제 코드북 구조와 정의·경계 사례를 관리하는 방식을 참고했다. 공식 사이트는21개 대분류와220개 하위분류를 설명하고 국가별 적용 과정에서 분류 의미가 달라지는 문제를 경계한다. 출처: https://www.comparativeagendas.net/pages/master-codebook (확인2026-11-04). Bevan(2019)의 코드북 조정 과정도 참고했다: https://doi.org/10.1093/oso/9780198835332.003.0002.

이 프로젝트의 CJ01~CJ18은 청주시 관측자료와 분석 목적에 맞춰 작성한 독립 초안이다. CAP 번호를 재사용하지 않았고, CAP와 직접 비교 가능한 공식 코드나 승인된 변환표가 아니다. 범주를 합치거나 나눌 때 기존 코드를 다른 의미로 재사용하지 않고 코드북 버전을 올린다. 기계가 단어 출현으로 자동 확정하는 사전도 아니다.

기준 파일: config/policy_topics_v1.json. 각 주제에 정의·포함·제외·긍정 예시·반례가 있다. 예시는 설명을 위해 작성한 가상 문장이며 실제 의원 발언의 확정 분류가 아니다. 교통/복지, 보건/체육, 농림/동물, 환경/에너지, 문화/보훈 등 경계에서 무엇이 실질적 정책대상인지 읽고 판단한다.

## 관측과 코딩

한 문서는 한 활동이며 문단 수를 활동건수로 세지 않는다. 의원 발언으로 검증된 본문만 읽는다. 시정질문은 분리된 의원 질문만 포함하고 집행부 답변을 보지표의 주제 근거로 섞지 않는다. 제목이나 인사말, 의원 직책, 단순 집단명, 사업비의 언급만으로 주제를 부여하지 않는다.

문서가 실제로 여러 정책대상을 다루면 복수 주제를 부여할 수 있다. 각 주제마다 정확한 본문 근거와 짧은 판단 이유를 남긴다. 비판·반대가 있다고 주제를 제외하지 않지만 해당 정책에 찬성하거나 선호한다고 해석하지 않는다. 인용을 의원 자신의 제안으로 혼동하지 않는다.

판정은 coded(근거 있는 주제), no_policy(정책주제를 부여할 수 없음), ambiguous(기준으로 확정하기 어려움)로 구분한다. no_policy/ambiguous에는 이유를 남기며 의원의 관심사가 없다는0점으로 바꾸지 않는다. 복수 주제의 문서 비중은 합계100%를 넘을 수 있다.

## 초기 검토 표본

현재 입력188건=5분발언175+시정질문13. 개발 표본40건은 시정질문13건 전체와 5분발언27건이다. 5분발언은1·2·3대 각7건,4대6건을 대수별로 돌며 선정하고, 대수 안에서는 서로 다른 의원을 순환한다. 문서 선택은 고정 시드와 본문 해시로 재현한다. 정당·지역구·예상 주제나 분류 결과를 표본 선정에 사용하지 않는다.

이 배분은 작은 대수·질문분리 사례를 적극 검토하기 위한 프로젝트 설계이며 확률표본이 아니다.40건에서 얻은 정확도를188건 전체나 모든 의원에게 일반화하지 않는다. 나머지148건도 아직 라벨이 없는 예비 자료일 뿐 자동으로 독립 평가용 정답셋이 되지 않는다. 코드북을 안정화한 뒤 사건/회기·중복문서·시점 누출을 고려해 별도 평가 표본과 정답 코딩을 설계한다.

입력이 갱신되면 표본 수·배분도 바뀔 수 있다. 생성 요약에서 실제 분모를 읽고 현재188/40/148을 코드의 영구 정답으로 쓰지 않는다.

## 검토 기록의 형식과 검증

생성 파일은 exports/topic-review/review_tasks.jsonl.gz(모든 문서의 검토 과제), development_sample.jsonl.gz(초기40건의 본문·공식 링크·빈 검토 양식), manifest.json(원문입력/코드북/출력 해시)이다. 모든 topic_ids와 검토자/판정은 빈 상태이며 사람 검토를 했다고 표시하지 않는다.

독립 검토자는 이 양식을 각자 별도 파일로 복사해 코딩한다. 다른 검토자의 결과를 보기 전에 기록한다. 실제 검토를 수행한 사람만 review_origin=human, reviewer_id, status=completed를 입력한다. 이 필드는 사람 검토의 기록 방식이며 검토자 실명·서명을 기술적으로 인증하는 시스템은 아니다. 모델이 만든 초안은 별도로 automated/draft로 보관하며 사람의 정답 자료로 계산하지 않는다.

각 라벨은 evidence_spans에 topic_id·start·end·quote를 기록한다. 범위는 저장된 member_text의 Unicode 문자 인덱스이며 end는 포함하지 않는다. 원문을 복사하고 start/end의 문자열이 quote와 정확히 같은지 확인한다. 원문·코드북 해시가 바뀌면 기존 코딩은 재검토 대상으로 돌린다. 한국어의 조사나 숫자·부정문을 임의 삭제한 문자열을 근거로 저장하지 않는다.

validate_annotation은 원문/코드북 버전, 검토 완료 상태, 허용 코드, 라벨별 근거 범위·인용문 정확성을 확인한다. 이것만으로 정책 의미가 올바르게 해석됐다고 증명하지는 않는다. 의미 검증에는 독립 코딩·불일치 조정과 원문 재독해가 필요하다.

자동 생성 파일을 직접 수정한 내용을 영구 검토 기록으로 취급하지 않는다. 수동 검토본은 archive/analysis_annotations/<codebook-version>/ 아래 별도 파일로 보존하는 계약을 사용하며, 이번 생성기는 이 폴더를 생성·덮어쓰기·수정하지 않는다. 사람 검토본의 수집·불일치 조정·성능 평가 기능은 다음 단계다.

## 공개 전 확인

분류표를 다듬을40건의 코딩과 불일치 기록을 먼저 남긴다. 이후 별도 검증 자료에서 주제별 정밀도·재현율·미분류·오류 사례·표본 수를 확인한다. 사람 검토가 없는 현재 단계에는 주제별 의원 순위, 관심사 점수, 정당·지역별 주제 차이를 표시하지 않는다. 위원회 기회 보정이나 임의 가중치도 적용하지 않는다. 기존 분석 HTML의 결과를 이번 분류표가 검증한 것처럼 바꾸지 않는다.


## AI 초안 단계의 구분(2026-11-04 추가)

40건에 대한 AI 초안은 archive/analysis_annotations/cj-topics-0.1/ai_draft_20261104.jsonl에 별도 보존한다. 이는 정책 질문·제안 문맥 중심의 비완결 초안이다. 전 문서 정독이나 독립 사람 검토를 수행했다고 표시하지 않는다. 라벨마다 원문에서 재현되는 근거와 이유·경계 쟁점을 붙였으며 topic_set_complete=false, evaluation_reference_eligible=false다. 확인한 주제 외에 누락된 주제가 있을 수 있다.

build_topic_review_drafts.py는 원문/코드북/검토ID/근거범위와 AI 초안 상태를 검사한다. 원문 변경·코드북 변경·중복 초안·잘못된 근거는 보류하고 원본을 수정하지 않는다. 이 검사를 통과했다는 것은 인용과 버전의 정합성만 확인했다는 뜻이며, 주제 판정의 정확도나 사람 정답셋이 됐다는 뜻이 아니다. validate_annotation은 여전히 AI 초안을 사람 완료 검토로 인정하지 않는다.

주요 검토 쟁점은 의료시설 입지와 의료서비스, 주차의 복지 수사와 복지정책, 분야별 조직 운영과 일반행정, 노동권과 일반 인권, 에너지시설과 환경영향, 기술 수단과 디지털정책의 경계다. 이주민 정착/다문화 지원은 기존18주제로 포괄하기 어려울 수 있어 범주 추가 또는 보조코드의 필요성을 검토한다. 현재 단계에서는 코드북을 임의 변경하거나 자동으로 추가 주제를 확정하지 않는다.

다음은 독립 사람 검토와 쟁점별 코드북 조정이다. 그 전에는 초안40건의 주제 분포를188건 전체의 관심사 분포로 사용하거나 의원 순위·정당 차이·정확도로 표시하지 않는다. 독립 사람 검토가 불가능할 때에는 그 한계를 유지한 탐색 초안으로만 제공한다.
