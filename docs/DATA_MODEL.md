# Data model v0.1

## Core entities

### Person
Stable human identity.
- person_id
- name
- aliases
- official_profile_url
- official_profile_code
- portrait

### Tenure
A person serving in one council scope and term.
- person_id
- council_scope
- term
- start_date
- end_date

### Temporal memberships
Separate ledgers for:
- party
- district
- standing committee
- special committee
- research group
- council office / committee role

Each row should include source evidence and effective period.

### Meeting
- meeting_id
- council_scope
- term
- session / sitting identifiers where available
- meeting_type
- committee_code
- committee_name
- date
- title
- publication_status
- official_url
- source_id
- content_sha256
- first_seen_at
- last_checked_at
- supersedes
- superseded_by

### Speech turn
- turn_id
- meeting_id
- speaker label as printed
- resolved person_id when evidence supports it
- role/title as printed
- start/end locations

### Bill / resolution
- source identifier / internal number
- agenda number where available
- title
- type
- proposer / representative proposer
- full proposer roster
- committee and plenary processing metadata
- official source URL

### Attachment link
No binary copy by default.
- parent_type
- parent_id
- title
- official_url
- official_attachment_id
- file_type
- first_seen_at
- last_checked_at

## Downstream-only fields

The archive must not create analytical judgments such as Q codes, EVENT clusters, P1-P7 stages, policy-interest labels, rankings, scores or probabilities. Those are generated by downstream analysis.
