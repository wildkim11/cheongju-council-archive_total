# 분석 기간 계산 기반 — 2026-11-04

## 이번 단계 결과

`analysis_periods.py`는 시작·종료일 양 끝을 포함한 구간 합집합·교집합·일수와
대수/전후반기 선택 해석, 프로필별 명시 재임기간과의 교차 계산을 제공한다.
불연속 대수/재임의 공백은 채우지 않고 중복/겹침/인접 구간은 한 번만 센다.
윤년, 단일 날짜, 6월30일/7월1일 경계, 보궐·사퇴 형태의 부분 재임을 시험했다.
시험의 대수 날짜는 합성값이며 실제 청주시의회 기간 근거로 사용하지 않는다.

기간 선택 계약은 `{start_date, end_date, periods:[{council_scope,term,half}]}`이다.
날짜 쌍만 또는 periods만, 둘을 함께 지정할 수 있다. 둘을 지정하면 교집합이다.
`half`는 whole/first/second이고 의회별 대수 번호는 독립적이다.
날짜 역전·존재하지 않는 날짜·누락 끝점·잘못된 조건 필드는 오류로 중단한다.
선택한 대수/전후반기에 근거가 하나라도 없거나 중복되면 전체 HELD이며
부분적으로 넓어진 기간을 반환하지 않는다. 유효하지만 교차 결과가 없으면 EMPTY다.

공식 기간 레지스트리 각 행에는 council_scope/term/half/start_date/end_date와
period_precision=exact_date, 공식 source_url, record_ref가 필요하다.
7월 전환이나 2년 전후반기라는 관례로 날짜를 생성하지 않는다.
현재 `config/analysis_periods.json`은 의도적으로 빈 상태다. 승인된 수집 경로로
대수 및 전후반기 근거를 보존·대조한 뒤 감사기를 확장하고 활성화해야 한다.
현재 감사기는 비어 있지 않은 레지스트리를 자동 수용하지 않는다.

재임 교차는 person_id+council_scope+term으로만 연결한다. 이름으로 다른 프로필을
합치지 않는다. 명시 재임 근거 외 미확정 행이 있으면 PARTIAL로 표시하고
분모는 null이다. 후보 행 자체가 없으면 HELD이며 0일로 단정하지 않는다.
중복 재임행은 일수를 부풀리지 않는다. 확정 구간의 recorded_days는 기록된
달력상 재임일수이며, 실제 의안·발언 기회나 의정 성과를 뜻하지 않는다.
이 모듈은 원문을 재조회하거나 사람 검토 승인을 만들지 않는다.

## 입력 준비도와 다음 작업

해시 검증한 현재 원장의 명시 시작·종료일/기간정밀도/공식URL 조건 충족 행:

| 자료 | 전체 행 | 명시 기간 조건 충족 | 기간 조건 미충족 |
| --- | ---: | ---: | ---: |
| 재임 | 435 | 10 | 425 |
| 정당 | 44 | 0 | 44 |
| 위원회 | 207 | 33 | 174 |
| 지역구 | 167 | 9 | 158 |

행 수는 고유 인물 수나 검증된 전체 경력 수가 아니다. 상세 계약과 입력 해시는
`reports/analysis-period-readiness-latest.json`으로 남긴다.
`python scripts/audit_analysis_period_readiness.py`로 현재 자료에서 재생성한다.
감사기는 공식 사이트 요청 0회, 기존 원장/집계 변경 0건이다.
기존 오프라인 자동가공에 감사를 연결해 보고서를 매 실행 갱신·저장하고 산출물에도 포함한다.

선수 필터는 아직 활성화하지 않는다. 검증된 프로필 간 인물 교차표, 범위를 명시한
완전한 당선/재임 사건 이력이 없어 초선·재선·3선 이상을 추정할 수 없다.
중복 재임행을 선수로 세거나 현재 정당을 과거에 소급하는 코드는 추가하지 않았다.

다음은 저장 원문에서 대수/전후반기·부분 재임 근거를 정리하고 인물 교차표와
선수 산정 계약을 갖추는 단계다. 공식 재조회가 필요하면 기존 GitHub Actions
macOS 수집 경로만 사용한다. 이후 동일 계약을 HTML 시작·종료일/대수 선택과
모든 분석 화면에 연결한다. 이번 단계는 계산 기반 구현이며 HTML 연결 완료가 아니다.
