## 실제 결과

공통 응답 보관소 `archive/source_responses`에는 명부의 디코딩된 HTML 원문이 이미 보존돼 있었다.
명부 수집기만 살펴 원문이 없다고 판단해서는 안 된다. 새 공식 요청은 하지 않았다.
현재 명부 응답 16개를 각각 원문 SHA-256·UTF-8 크기·응답 원장과 대조하고 다시 파싱했다.
POST URL은 대수를 구분하지 않으므로 응답의 대수 표기·프로필 URL을 함께 확인했다.
세션 토큰이 포함된 요청 파라미터 해시에서 대수를 역추정하지 않았다.

현재 의원 프로필의 원문 대조는 이번 124개와 별개다. 이미 보존된 다른 원문까지 없다고
단정하지 말고, 대응 응답 원장과 선택조건을 찾아 추가 연결한다.

## 산출물과 운영

- `scripts/build_profile_history_evidence.py`: 공식 사이트 요청 없는 파생 원장 생성·검증.
- `exports/profile-history/profiles.jsonl`: 프로필별 원장 행번호/행SHA·개인기간·보류사유·원문응답 경로/해시.
- `exports/profile-history/link_candidates.jsonl`: 코드 종류별 후보, 실제 관찰 대수와 중간 미관찰 대수.
- `exports/profile-history/manifest.json`, `reports/profile-history-evidence-latest.json`: 입력·출력 해시와 분모.
- 오프라인 가공 Actions 및 정기수집의 게시 전 후보 검증에 연결. 원본 수집은 기존 macOS 경로 유지.

`mcode`는 대수에 속한 코드이므로 반복 코드·이름·같은 사진만으로 영속 인물ID를 만들지 않는다.
현재 `f_code`와 역사 `mcode`도 숫자 문자열이 같다는 이유로 연결하지 않는다. 사진 해시는
이미지의 동일성을 확인하며 인물 신원의 독립 인증이 아니다. 이름만 같은 기록·통합 전후 범위는
자동으로 묶지 않는다. 명부 원장/원문/사진 훼손은 저장 전에 실패한다.

개별 재임 10행은 의회 전체 대수의 시작/종료 근거가 아니다. 관찰 대수가 1·3대뿐인 후보의
중간 미관찰 2대는 낙선·불출마가 확인됐다는 의미가 아니다. 선수는 당선 이력과 완전한 경력,
통합 이전 포함 여부, 선택 시점까지인지 전체 경력인지가 정해진 뒤 별도 계산한다.
