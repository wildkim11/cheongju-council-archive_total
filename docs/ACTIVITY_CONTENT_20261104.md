# P07 활동 본문·질문/답변·첨부 연결

## 먼저 정정한 구성 표기

앞선 단계의 활동204건 구성 표기(175+13+16)는 잘못됐다. 실제 기초집계와 본문
판정 원장을 다시 대조한 결과는 다음과 같다. 총204건/의안886건/참여11578행은 변함없다.

| 자료 | 기초집계 포함 | 검증 의원 본문 | 본문 경계 미검증 |
|---|---:|---:|---:|
| 5분발언 |188|175|13|
| 시정질문 |16|13|3|
| 합계 |204|188|16|

서면질문16건은 개인 귀속 보류이며 이204건에 포함되지 않는다. 별도 원자료 목록에서
게시물 표기 인명과 질문·답변 첨부를 확인한다. 활동707건 중 나머지487건의 최신
개인 귀속/본문 연결은 미완료다. 과거707건 원자료 내장은 별도 버전으로 유지한다.

## 연결 계약

- 자료 기준은 선택 기초집계의 `source_commit`. 이번 HTML은
  `f978de20298e357f21a5e3c87d4b616d1a3339be`를 사용한다.
- 고정 원장 manifest의 SHA-256·행수, 정확한 행좌표·원천ID·날짜·범위·표기인명·제목·URL로
  연결한다. 인명만으로 귀속시키지 않는다. manifest 경로·크기·압축해제 상한도 검사한다.
- 의원 본문은 text-input 배포와 count 배포의 gate 해시 일치, 인물ID·대수·활동ID·
  원문 게시물 해시·의원본문 해시·회의록 증거를 검증한다. 이 단계가 사람 의미검토를 뜻하지 않는다.
- 시정질문13건은 질문 본문과 집행부 답변의 경계·회의록SHA·질문동일성·답변SHA를 대조한다.
  집행부 답변은 접힌 영역에 따로 표시하고 의원 관심 분석에서 제외한다.
- 나머지 기초 포함16건은 게시물 보존 원문을 보여주되 의원 본문 경계 미검증으로 표시한다.
  시정질문 원문에는 집행부 답변이 섞일 수 있음을 알리고 분석 입력으로 사용하지 않는다.
- 서면질문은 개인 귀속 보류 상태를 유지한다. 질문/답변 파일의 동일 source_id와
  `gb=qna/ans`를 각각 확인한다. 개인판에 전체 보류 원자료를 넣지 않는다.
- 첨부 공식링크·기준 버전 큐 상태·보존 경로/해시를 구분한다. 큐 확인 실패 시 상태만
  unknown으로 내리고 링크는 유지한다. 첨부 바이너리를 이 UI에서 수집하거나 본문검증으로 승격하지 않는다.
- TXT에는 원문·자료 커밋·행좌표·해시·분리된 질문/답변·첨부 링크/상태·귀속보류를 보존한다.
- 통신/해시/연결 오류는 해당 본문 표시를 중단한다. 닫힌 창에 늦은 응답이 돌아오거나
  로딩 도중 집계 기준이 바뀌면 적용하지 않는다. 자료·점수·귀속 판정을 변경하지 않는다.

## 별도 최신 첨부 checkpoint 확인

이번 작업 중 확인한 저장소 HEAD `0cae211cd53b3d44fd35d1f263f57a8309ddf813`에서
기존 macOS 재시도 결과가 보존됐다.1891URL 중18다운로드/0실패/1871대기/2크기보류.
독립 바이트 감사 PASS:18고유파일·33195426bytes, 큐SHA
`58e17750ea5e594ea16b7773ceb383ade8e82b86803572d4eee85ce12bcd6f49`.
JPG14건 보존과8MiB초과2건 차단 전환이 실제 큐에서 확인됐다. 남은1873건이 있으므로
