# OCR 검토 기록 수용 전 검증 — 2026-11-04

## 목적과 현재 상태

검토 HTML에서 내보낸 JSONL/JSON 백업을 고정 원문·OCR·픽셀 근거와 대조한다.
실제 사용자 검토 파일은 아직 제출되지 않았다. 현재 결과는 `NO_USER_INPUT`,
검토 입력0·분석 사용0·의미승인0이다. 합성 시험 기록을 사람 검토 실적으로 집계하지 않는다.

이 절차는 입력 형식·근거 일치 검증이다. 전사문의 정확성, 검토자 신원, 실제로 원문을
읽었는지는 독립적으로 인증하지 않는다. 유효한 전사 기록도 `VALIDATED_NOT_APPROVED`이며
분석/의미 승인으로 승격하지 않는다. 의원 귀속·정책 관심·정답 전사 자료와도 구분한다.

## 검사 범위

- 검토 HTML의 내장 묶음SHA와 고정 커밋, 해당 Git 객체의 검토 assets/OCR manifest를 대조.
- 각 OCR 압축문서SHA/내용·원본SHA·전처리 픽셀SHA·단어좌표·출처 링크·이미지SHA 확인.
- 현재 저장소의 원문/OCR/픽셀 근거가 달라진 기록은 오래된 근거로 보류.
- 검토 행의 원본/버전/링크를 바꾸거나 임의 승인필드를 붙일 수 없음.
- 대조기록은 검토자·원문확인·전사문·시간대 포함 시각, 보류는 검토자·사유·시각을 요구.
- 미검토 행에 숨은 수정이 있으면 거부. 초안·미검토를 대조 완료 건수에 포함하지 않음.
- 한 행이라도 손상/중복/불일치하면 파일 전체를 미적용. 검증 실패 시 이전 결과파일을
  덮어쓰지 않음. 전체 입력은 크기/행수 상한을 적용.
- JSONL과 기존 검토 HTML의 전체JSON 백업을 지원. 브라우저 core가 만든 정상기록과
  Python 수용기 사이의 호환성을 시험함.

## 사용 방법

```sh
# 기존 검토 묶음의 원문 근거만 검사: 실제 리뷰를 생성하지 않는다.
python scripts/validate_ocr_review_intake.py --packet /path/OCR_review.html

# 사용자가 내보낸 검토 기록을 검사해 명시적으로 지정한 로컬 파일에 결과 보관.
python scripts/validate_ocr_review_intake.py --packet /path/OCR_review.html \
  --reviews /path/OCR_reviews.jsonl --output /path/private-intake-result.json
```

`--output`은 NO_USER_INPUT 또는 VALIDATED_NOT_APPROVED인 경우에만 쓴다.
HELD 오류는 종료코드2와 사유를 반환하고 기존 결과는 유지한다. 결과에 포함된
`declared_checked_transcriptions`는 유효한 제출행의 자기기록 건수이며 독립적으로
확인한 정확도/사람 검토 건수가 아니다. `analysis_usable_records`와
`semantic_approved_records`는 항상0이다.

고정 커밋이 얕은 로컬 checkout에 없으면 그 snapshot을 먼저 GitHub 저장소에서
준비해야 한다. 검증기 자체는 원격 fetch나 공식사이트 요청을 하지 않는다.
검토자의 이름·수정문·판정 기록을 GitHub에 자동 커밋하는 기능도 없다.

## 자동화와 검증

기존 오프라인 작업에서 검토 HTML을 생성한 뒤, 사용자 입력 없이 묶음 계약을 검사한다.
진단 결과는 Actions artifact의 `ocr-intake-no-user.json`에 함께 보관한다.
가공자료와 사용자 입력을 섞어 사람 검토가 생긴 것으로 표시하지 않는다.

기존519시험에 수용기15사례를 추가했다. 실제21건 HTML의 묶음·OCR문서·이미지
검사를 통과했고 NO_USER_INPUT/0건을 확인했다. 별도 scratch의 합성21행으로
브라우저→Python 수용 호환을 확인했으며 해당 합성 기록은 저장소·사용자파일·
프로젝트 실제 검토 실적에 반영하지 않았다.

## 다음 순서

실제 사용자 기록이 생기면 이 절차로 수용 후보를 분리한 뒤 원문 대조·필요한 추가검토를
진행한다. 그 전에도 독립적으로 진행할 수 있는 시작일/종료일·대수 선택과 재임이력
기반을 정비한다. 선수/비연속재임·전후반기·당시소속·기회 보정은 기존 요구 명세를
유지하며 자료 없이 추정하지 않는다. 기존 마스터/개인/검토 HTML은 이번 단계에서
변경하지 않는다. 첨부백로그/실기기 검수/일일수집 반복 관찰도 계속 남는다.
