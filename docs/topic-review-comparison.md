# 주제분류 검토 대조

## 현재 단계

2026-11-04: AI 초안 40건·원문 근거 66구간 다음 단계로 검토 입력 검증·대조 기능 구현. 전체 Python 테스트 399개 통과. 실제 사람 검토 0건, 정확도·관심사 점수 산출 없음. 검토 화면은 아직 구현 전.

## 실행

```sh
python scripts/compare_topic_reviews.py
python scripts/compare_topic_reviews.py --reviews /path/to/human_reviews.jsonl
```

첫 명령은 입력 없는 상태를 명시적으로 기록한다. 두 번째 명령은 원문·코드북·검토 과제·AI 초안의 현재 스냅숏을 확인하고 제출된 검토를 대조한다. 보고서: `reports/topic-review-comparison-latest.json`. 자동 수집 또는 기존 주제 초안 보고서를 사람 검토 결과로 덮어쓰지 않는다. 현재 자동 실행에는 연결하지 않았으며 운영자가 명시적으로 실행한다.

## 입력 규칙

기존 `exports/topic-review/development_sample.jsonl.gz`의 해당 과제 필드를 유지하고 다음 필드를 사람이 작성한다.

- `case_id`, `activity_id`, `member_text_sha256`, `codebook_sha256`: 현재 과제의 값을 그대로 유지.
- `status`: `completed`, `review_origin`: `human`, `reviewer_id`: 공백 없는 식별자. 공개 저장소에는 개인 연락처·이메일 대신 가명 식별자 권장.
- `full_text_read`: 본문 전체를 읽은 경우에만 `true`.
- `review_method`: AI 초안을 보지 않고 판단한 `independent`, 또는 초안을 참고한 `ai_assisted`.
- `reviewed_at`: 검토 일시.
- `decision`: `coded`, `no_policy`, `ambiguous`; 정책 주제가 있으면 `coded`와 `topic_ids`를 작성.
- `rationale`: 판단 이유. `evidence_spans`: 각 주제마다 원문 문자 시작·끝 위치와 정확히 일치하는 인용문.
- `change_reason`: AI와 주제 집합 또는 판단이 다르면 수정 이유 필수.

원문·코드북·과제 불일치, 부정확한 인용, 미완료/자동 검토 선언, 같은 검토자·과제의 중복 제출은 보류한다. 중복은 첫 제출을 임의 채택하지 않고 모두 보류한다. 수정본은 명시적으로 정리한 제출 파일로 재실행하며 원본 제출 이력은 별도로 보존해야 한다.

## 해석의 한계

사람이라는 선언과 독립 검토 여부는 입력자의 자기보고이며 신원을 인증하거나 실제 독립성을 입증하는 기능이 아니다. AI와 사람의 일치는 정확도가 아니다. 여러 사람이 제출한 결과는 개별 비교로 남고 합의·다수결·최종 분류로 자동 승격하지 않는다. 골드 정답·학술 신뢰도·의원 점수 산출은 하지 않는다. 보류가 있으면 보고서의 `held`를 함께 확인한다.

## 원문 검토 화면 (2026-11-04)

`python scripts/build_topic_review_ui.py`로 `exports/topic-review/review.html`을 생성한다. 원문·코드북·AI 초안이 들어 있는 단일 HTML이며 공식 사이트 추가 접속 없이 사용할 수 있다. GitHub의 정규 offline 가공과 macOS 수집 후보 검증에서도 같은 자료 묶음으로 다시 생성한다. 기존 Stage47 화면은 변경하지 않는다.

1. 검토자 식별자를 입력하고 40개 과제에서 하나를 고른다.
2. 의원 본문 전체와 펼쳐 볼 수 있는 18개 분류 기준을 읽는다. 근거 구절을 선택하고 주제를 지정해 인용을 추가한다.
3. 판단·이유·분류 경계를 기록하고 본문 전체 검토 확인 후 완료한다.
4. 완료 검토를 JSONL로 내려받아 `compare_topic_reviews.py --reviews 파일경로`로 다시 검증한다. 내려받기는 저장소 제출·업로드가 아니다.

AI 초안은 처음 숨김. 열면 해당 과제의 검토 방식을 AI 참고로 기록한다. 숨긴 초안과 다르다는 피드백으로 독립 판단을 유도하지 않도록 분류 경계 설명은 모든 검토에서 받는다. 편집하면 완료 상태가 해제된다. 입력값은 localStorage에 저장하지만 기기/브라우저별로 제한될 수 있으므로 JSON 작업 백업을 별도로 내려받는다. 복원은 동일 자료 스냅숏만 허용하며 완료 상태를 해제하고 기존 AI 열람 이력을 유지한다. 다른 기기·외부에서 이미 본 AI 초안 여부는 확인할 수 없으므로 독립성은 여전히 자기보고이다.

근거 위치는 JavaScript UTF-16 인덱스를 Python 유니코드 문자 좌표로 변환한다. 인용은 원문과 정확히 대조한다. 내용은 textContent/value로 표시하고 데이터의 `<` 문자를 JSON에서 이스케이프해 원문에 포함된 마크업 실행을 방지한다.

검증: Python 전체403개 및 jsdom 상호작용 검증(40과제/18주제, 숨김, 필수입력, 완료·내려받기, 편집해제, 초안 열람유지, 유니코드 인용 좌표, 마크업 비실행) 통과. 테스트는 가상 검토이며 사람 검토 건수에 포함하지 않는다. 네이티브 브라우저·모바일 화면·실제 파일 저장 완료는 아직 확인 전이다.

## 검토자 간 비교 (2026-11-04)

대조 명령은 `reviewer_comparison`을 추가한다. 같은 과제의 서로 다른 검토자를 쌍으로 비교해, A에게만 있는 주제/B에게만 있는 주제와 판단 차이를 보존한다. 독립 검토(자기보고)끼리의 쌍과 AI 참고가 포함된 쌍은 구분한다. 같은 검토자·과제의 중복은 모두 보류한다. JSONL 구문 오류/비객체/잘못된 식별자·일시는 해당 행을 보류하고 나머지 검토를 계속 처리한다. 원본 입력 파일은 변경하지 않는다.

두 검토자가 모두 `ambiguous`인 경우 `unresolved`로 남기며 합의로 세지 않는다. 검토가 없으면 `no_reviews`, 한 과제에 검토자가 한 명뿐이면 `insufficient_overlap`이다. 일치율·정확도·신뢰도 계수는 산출하지 않는다. 같은 과제나 검토자를 공유하는 비교 쌍은 독립 관측 표본이 아니므로, 쌍 수를 표본 수처럼 취급하거나 가설 검정에 사용하지 않는다. 다수결이나 최종 정답 승격도 없다.

검토 HTML에서 `대조 결과 불러오기`로 `reports/topic-review-comparison-latest.json`을 선택하면 과제별 검토자·주제·근거·이유·차이를 펼쳐 본다. 원문 보기 버튼으로 해당 과제로 이동한다. 입력 보류 이유도 확인할 수 있다. 원문/코드북/스냅숏 불일치와 표본 내 부정확한 인용을 거부한다. 이 화면의 40과제 밖 검토는 세부를 표시하거나 검증하지 않고 개수만 별도 표시한다. 가져온 파일의 집계 숫자를 신뢰해 표시하는 대신, 표본 내 검토 행에서 다시 집계한다. 출처 일치 확인은 사람 신원·독립성을 인증하는 기능이 아니다. 파일은 자동 업로드되지 않는다.

검증: 신규 Python 11회귀, 전체414개 및 기존·신규 jsdom 상호작용 검증. 가상 두 검토자의 주제 차이/AI 참고 구분·변조 인용 거부·스냅숏 불일치 거부·자료 없음 표기를 확인했다. 실제 사람 검토 0건, 일치율/정확도/신뢰도 계수/관심사 점수 없음. 실제 브라우저·모바일 확인은 미완료 유지.

독립성 보완: 비교 결과 열람은 해당 과제에 `peer_review_seen`을 남기며 완료를 해제한다. AI를 직접 열지 않았으면 `peer_assisted`, AI도 열었으면 `ai_assisted`와 peer 이력을 함께 내보낸다. 백업 복원으로 참고 이력이 지워지지 않게 한다. Python은 peer 열람을 선언하고도 independent라고 제출한 행을 거부한다. 참고 쌍 수는 AI/peer가 중복될 수 있으므로 서로 배타적인 표본 수로 해석하지 않는다.
