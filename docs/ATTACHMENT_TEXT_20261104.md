# 첨부 본문 추출 — 2026-11-04

## 이번 단계의 결과와 한계

기존 macOS 수집으로 보존된18파일 중 PDF4개를 쪽별로 처리했다. 전체129쪽에서
122쪽은 텍스트가 나왔고7쪽은 글자가 추출되지 않았다. 이미지14개와 해당7쪽은
OCR 또는 시각검토 대상으로 남긴다. 원본을 변경하지 않았으며 공식사이트 요청은0이다.

이것은 기계 추출 결과이지 내용 검증 완료가 아니다. 텍스트가 있는 쪽도 표·다단·
그림 속 글자·읽기순서·누락이 있을 수 있다. 사람 검토0쪽, 의미검증0문서,
의원귀속허용 false를 유지한다. PDF표지2쪽의 표시를 참고 점검했지만 문서 전체의
정확도 검수나 사람검토 완료로 승격하지 않았다. 자료의 주최·위원회 표기를 특정
의원의 관심 주제나 개인 발언으로 변환하지 않는다.

## 저장·증거 계약

- `exports/attachment-text/manifest.json`: 큐/원장 기준 해시·추출기 버전·URL별 상태·
  파일별 원본 SHA/크기·쪽별 문서 압축파일 SHA와 범위.
- `exports/attachment-text/<원본SHA>.json.gz`: 1기준 PDF쪽 번호, 원문 자동 추출문,
  쪽별UTF-8 텍스트SHA·비공백 글자수·미검토/OCR대상 상태.
- `reports/attachment-text-latest.json`: 추출·OCR대상·수집미완료의 분모를 분리한 요약.
- URL·원장데이터셋·행좌표·원장SHA 연결은 링크 필드의 정확한 URL 일치로만 구성한다.
  제목·인명·부분문자열로 연결하지 않는다. 근거가 없으면 참조목록을 비워 둔다.
- 원본경로·해시·크기·형식헤더, 원장SHA·행수의 무결성 오류는 추출 전에 중단한다.
- 지원하지 않는 이미지/HWP/ZIP 등을 PDF로 오인하지 않는다. 이미지=OCR대상,
  기타컨테이너=미지원, 미수집1873URL=not_downloaded로 구분한다.
- `PASS`는 입력 무결성과 처리기 수행을 뜻한다. 전체 첨부 수집/문서내용 검증 완료가 아니다.

## 반복 자동화

`process-attachment-text.yml`은 GitHub에 보존된 파일만 Ubuntu에서 가공한다.
공식사이트 수집은 기존 GitHub Actions macOS 경로로 유지한다. 첨부 큐/바이너리/
원장 manifest·처리기 변경 시 실행하고, 수집 작업과 같은 concurrency그룹으로
원격 데이터 쓰기 충돌을 방지한다. 추출 결과가 다시 이 워크플로를 재호출하지 않는다.

같은 원본 SHA·추출기/코드 버전의 정상 결과는 압축파일과 쪽 해시를 검증해 재사용한다.
파일명이나 큐의성공표시만 믿지 않는다. 같은 파일을 가리키는 URL은 중복 추출하지 않는다.
한 번에 새PDF10개, 파일당8MiB/500쪽, 추출문8MiB, 명령/파일별 시간 상한을 적용한다.
남은 파일은 processing_pending으로 다음 실행에 넘긴다. 추출 오류는 따로 보류하고
새 파일 처리를 막지 않는다. 오류 재실행은 `--retry-errors`로 선택할 수 있다.
추출기/코드 버전이 바뀌면 새로 처리한다. 실패나 무지원 원문을 성공으로 올리지 않는다.

```sh
python scripts/extract_attachment_text.py
python scripts/extract_attachment_text.py --retry-errors
```

필요한 로컬 도구는 Poppler `pdfinfo`와 `pdftotext`. 자동화에서는 설치 여부를 확인하고
부족하면 설치한다. 추출기 버전을 결과에 기록한다.
