## 2. 통합 모니터의 실행 범위 및 한도

모니터가 별도 macOS 환경에서 수행하는 읽기전용 흐름:

1. 저장본 전체 SHA-256 및 인덱스·export 정합성 사전 검증.
2. 공식 **제4대** 대수·회기·위원회별 목록 완전 탐색 및 현재 보존본 인덱스와 **신규 ID, 공개상태, 메타데이터, 공식 목록 누락·중복** 비교.
3. 현재 저장본에서 **기존 임시본 전부(현재 6건)**, 새로 확인한 원문 후보, 상태/메타데이터 변경 후보의 실제 공식 본문을 확인. 그다음 제4대 정식 회의록 4건과 과거 대수(1~3대) 정식본 4건을 **날짜 기반 회전 표본**으로 조회해 본문 정규화 SHA 비교.
4. 변화가 없으면 원본 수정 **0건**, 해시 비교 결과만 보존. 새 ID·본문/상태 변화가 확인되면 **검토 후보**만 기록. 서버 접근 장애/불완전 트리/호출 예산 초과는 출처 삭제로 간주하지 않고 **BLOCKED** 처리.
5. GitHub Actions 실행 요약과 경고·오류 주석, JSON 아티팩트를 제공한다. **오류 시 CI 실패 상태**를 반환하여 Actions 알림 설정에 연결할 수 있도록 준비했다. 외부 이메일/메신저 푸시가 실제 발송된 사례는 이번에 검증하지 않았다.

**설정된 강제 상한**
- 공식 제4대 트리 조회 최대 **80회** (실제 33회), 개별 HTML 원문 조회 최대 **20회** (실제 17회).
- 개별 요청 타임아웃 **12초**, 트리 응답 상한 **2MiB**, 원문 HTML 상한 **8MiB**, 본문 GET 사이 휴지 **0.35초**.
- 재시도 **0회**; 서버 오류는 재시도 폭주 없이 실패 기록으로만 남긴다.
- 기존 임시본 최대 10개 및 한 차례 신규 ID 최대 8개를 정상 동작의 보수적 상한으로 둔다. 초과 시 **BLOCKED**; 알 수 없는 사례를 임의로 누락시키지 않는다.
- **과거 정식본 전체를 한 번에 재조회하지 않는다.** 표본 회전은 정상적인 반복 실행이 이어질 때 커버리지를 넓히는 방식이며, 아직 무인 스케줄이 켜져 있지 않다.
- 모니터는 기존 원본이 **2,341건 등으로 늘어난 뒤에도** 현재 인덱스를 동적으로 읽을 수 있도록 `probe_official_term4_new_meeting_ids_macos.discover(...,baseline_policy="current")` 모드를 추가. 최초 2,339건 전용 엄격 QA 모드 `"initial"`도 그대로 유지.

## 3. 변경후보를 실제 격리 증분수집기에 전달하는 법

종전 수집기는 **정식 회의록의 현재 메타데이터가 그대로인 본문만 수정된 사례**를 기본 `incremental` 선택으로는 재수신하지 않았다. 이를 해결하기 위해 다음 인터페이스를 **실운영 잠금을 유지한 채** 격리환경용으로 추가했다.

```python
collect_integrated_minutes.run_sync(
    "incremental",
    disposable_archive_root,
    force_body_ids={"cheongju_integrated:minutes-3999"},
)
```

- `force_body_ids`는 정상적인 **변경 확인 후보의 기존 meeting_id**만 허용하고, 저장 인덱스에 없으면 즉시 중단한다.
- 명시된 기존 정식본은 메타데이터가 같아도 본문 재수신 대상으로 포함한다.
- 실제 원본 ROOT에 이 파라미터를 지정해도 기존 `LIVE_ARCHIVE_INCREMENTAL_SYNC_DISABLED` **하드 잠금이 먼저 작동**한다.
- 파이프라인의 최종 자동 배포/권한 승인/실제 GitHub 저장소 원본 반영은 여전히 구현상 **OFF**다.

## 4. 장애 보고 및 일정 설계 — 아직 비활성화

- **제안 일정:** 매일 오전 **07:30 KST** (UTC 전날 22:30), GitHub macOS Actions.
- **실제 동작:** 수동 `workflow_dispatch`만 가능. `schedule:` 없음, push-triggered 공식 재검증도 OFF.
- 조회 실패·HTML 파싱 실패·예산 상한 초과: `BLOCKED_INCONCLUSIVE_SOURCE_OR_BUDGET` 및 workflow 실패, 운영 원본 변경 불허.
- 추가·변경 후보: GitHub Actions **경고 주석, 단계 요약, JSON 증거**, 자동 반영 불허.
- **기본 GitHub Actions 실패 알림은 사용자의 저장소/계정 알림 설정에 종속적**이다. 특정 이메일 또는 메신저가 자동으로 통지됐다고 주장하지 않는다. 향후 별도 승인하에 Issue dedup/전송 연동 가능.
- 파일 `reports/official-incremental-monitor-readonly-latest.json`에는 원본 HTML이나 회의록 전문 없이 **식별자·목록·본문 해시·오류 분류만** 보존한다.
